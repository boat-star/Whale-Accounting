## 2026-10-18 · 立项与方案

产出《鲸鱼记账-需求分析与技术方案设计文档》（v0.1 → v0.2），内容包括需求分析、
架构设计、技术选型三部分，落到可执行的工程约定：表结构、IPC 契约、目录结构、验收标准。

技术选型的判断依据来自实机探测，而不是纸面对比：

```
Windows 11 10.0.26300（预览版）
.NET SDK：无（仅 6.0 / 7.0 运行时）
Rust 1.95.0、Node 22.22.2、pnpm 10.29.2
WebView2 Runtime 155.0.4283.62
VS2022 Community + Windows SDK 10.0.26100
```

结论是 Tauri 2 + React 19 + Rust + SQLite(SQLCipher)，加权得分 4.50，高于
Electron 3.65 / WPF 3.55 / WinUI 3 3.00。决定性的一条是：WPF/WinUI 需要先补
1.5–2.5 GB 环境，Tauri 可零前置开工。

## 2026-10-18 · 按 Tauri 实现

Rust 侧写完了数据层（表结构、迁移、余额重算）、业务命令（交易/账户/分类/预算/报表/
导入导出/备份），`cargo check` 通过；前端 9 个页面写完，`tsc --noEmit` 无错；
`pnpm tauri build` 编译出 exe。

**然后卡在渲染上。** 窗口能创建，但内容区全黑。

排查路径（每一步都排除了一个假设）：

1. 屏幕截图黑屏 → 怀疑 GPU 合成层无法被捕获，关 `--disable-gpu` 重试 → 仍黑
2. PrintWindow 抓取 → 仍黑，说明不是捕获方式问题
3. 同样的 `dist` 用无头 Edge 打开 → **渲染完全正常**，说明前端本身没问题
4. Tauri 日志只有 `Started`、没有 `Finished` → 资源加载被阻断
5. 怀疑系统代理拦截 `tauri://` 本地协议 → 加 `--no-proxy-server` → 无效
6. 清 WebView2 数据目录 → 无效
7. 查 `msedgewebview2.exe` 子进程 → **一个都没有**，渲染进程根本没起来
8. 脱离执行沙箱启动 → 子进程出现（13 个），截图从纯黑变白，但页面仍是空白

到第 8 步可以确认两件事：一是沙箱对 WebView2 子进程有影响，二是即便起来了，
页面资源仍未加载。此时已投入多轮排查，继续深入的成本不可控。

**决策：换 Electron。** 自带 Chromium，不依赖系统 WebView2；代价是体积从理论上的
十几 MB 涨到 100 MB 左右。对一个本地记账工具来说，稳定性优先级高于体积。

## 2026-10-18 · Electron 移植与五个坑

数据层从 Rust 平移到 Node（sql.js，纯 WASM，不需要原生编译），业务规则保持一致：
金额存「分」、转账不计收支、余额派生、日期不带时区。前端只换了 IPC 桥接层。

### 坑 1：`ELECTRON_RUN_AS_NODE=1`

环境里带着这个变量，Electron 会以 Node 模式启动，`--version` 打印的是 Node 版本号，
窗口一个都不开。启动前必须 `env -u ELECTRON_RUN_AS_NODE`。

### 坑 2：GPU 进程反复崩溃

日志里 `GPU process exited`、`0x80000003`，窗口白屏。试过 `--disable-gpu`、
`use-angle=swiftshader`、`disable-gpu-shader-disk-cache`、清 GPU 缓存目录，都不稳定。
最终有效组合：

```js
app.disableHardwareAcceleration();
app.commandLine.appendSwitch("disable-features", "SkiaGraphite,Vulkan,DawnCache");
app.commandLine.appendSwitch("in-process-gpu");
app.commandLine.appendSwitch("disable-gpu");
```

`in-process-gpu` 把 GPU 线程收进主进程，避免独立 GPU 进程在双显卡环境下争抢资源后
被强杀。记账界面是纯 2D 表单与图表，软件渲染完全够用。

### 坑 3：`file://` 下 ES Module 被 CORS 拦截

`loadFile()` 加载页面时 CSS 生效、JS 从不执行。原因是 `file://` 被视为不透明源，
`<script type="module">` 被 CORS 策略拒绝，而且控制台里连请求记录都没有。

改为自定义 `app://` 协议，注册为 `standard + secure + supportFetchAPI + corsEnabled`，
再用 `protocol.handle` 把请求映射到 `dist` 目录。资源路径同时改为相对路径。

### 坑 4：打包后渲染进程沙箱崩溃

打包版一启动就 `render-process-gone`，源码方式运行却正常。差异在于打包模式会启用
渲染进程沙箱。`webPreferences: { sandbox: false }` 之后恢复正常。

### 坑 5：pnpm 的符号链接

`node_modules/sql.js` 是符号链接，直接 `cp -r` 复制到发布目录会得到一个空壳，
打包版启动即报找不到 wasm。要用 `cp -rL` 跟随链接复制实体文件。

顺带解决：Tauri 打包时 NSIS 需要联网下载，而网络代理返回 502；改用本机已缓存的
NSIS 3.11 手工封装安装包。

## 2026-10-18 · 形象换成鲸鱼娘

最初的应用图标是手写绘制脚本画的一只简笔鲸鱼。按需求改成 DeepSeek 风格的鲸鱼娘：

- 用 AI 生成两张立绘（精神满满 / 抱膝睡着），风格统一：藏青到天蓝的渐变长发、
  鲸鳍发夹、呆毛、鲸尾、海军领围裙
- 纯色背景用洪泛填充抠成透明，alpha 再收缩一像素去掉浅色描边残留

- 图标 = 圆角方块 + 淡蓝渐变底 + 头像，生成 16–1024 全尺寸（ico / png）
- 组件层保留原 API（`size` + `mood`），内部改为按尺寸选头像或全身立绘，
  30–64 px 用头像保证五官可辨，大尺寸用立绘

## 2026-10-18 · 修图标：快捷方式 / 任务栏 / 标题栏

打包后发现三个位置还是 Electron 的原子图标：桌面快捷方式、任务栏、窗口标题栏。

原因有两层：

1. **重命名 exe 不会改图标**。发布目录是把 `electron.exe` 改名为 `鲸鱼记账.exe`，
   但 PE 里的 `RT_GROUP_ICON` 资源仍是 Electron 的。资源管理器、任务栏、快捷方式
   默认都从这里取图，所以看到的是原子。
2. **快捷方式没指定图标**。`CreateShortcut` 只给了目标路径，图标实际来源还是目标 exe。

处理：

```bash
# 1) 把图标与版本信息写进 exe（rcedit 作为 devDependency）
rcedit "release/鲸鱼记账/鲸鱼记账.exe" \
  --set-icon app/build/icon.ico \
  --set-file-version 1.0.0.0 --set-product-version 1.0.0.0 \
  --set-version-string ProductName 鲸鱼记账 \
  --set-version-string FileDescription "鲸鱼记账 - 本地记账本"
```

```nsis
; 2) 快捷方式显式指向带图标的 exe
CreateShortcut "$DESKTOP\鲸鱼记账.lnk" "$INSTDIR\鲸鱼记账.exe" "" "$INSTDIR\鲸鱼记账.exe" 0
```

3) 窗口图标本来就由 `BrowserWindow({ icon: build/icon.png })` 指定，标题栏与任务栏按钮
   取的是它，这部分无需改动。

验证方式：从 `icon.ico` 里取出 256px 图的前 400 字节，在 exe 里做字节匹配（`True` 即写入成功）；
再静默安装一次，确认安装后的 exe、桌面与开始菜单快捷方式都存在且指向它，最后清理测试痕迹。

注意：文件属性里的 `ProductName` / `FileDescription` 也要一起改，
否则右键属性显示的是 "Electron"，任务管理器的进程描述同样是它。

## 2026-10-18 · 三处交互：文案分时段、鲸鱼娘、图表悬停

### 概览文案

原来副文案只有一句，且只按支出金额分三种。现在按 **时段 × 今天是否有支出** 组合出 14 句：
凌晨 / 早上 / 上午 / 中午 / 下午 / 晚上 / 深夜，每个时段各有「已花钱」「未开张」两个版本；
当天支出超过 ¥500 时统一覆盖成提醒去看明细的那句。

### 鲸鱼娘

- 鼠标悬停：上浮 7px 并放大 3.5%，缓动用了轻微回弹
- 鼠标点击：0.6 秒的弹跳动画（缩放 + 左右摆），同时弹出对话气泡说一句随机台词，2.4 秒后消失
- 常态有一个 4.6 秒周期的轻微上下浮动；`prefers-reduced-motion` 下全部关闭

踩坑：气泡最初写成 `right: calc(100% + 10px)` 且只有 `max-width`。绝对定位元素在
「右侧偏移为负」的情况下可用宽度被算成 0，文字于是逐字竖排。改成 `width: max-content`
并保留 `max-width` 后正常折行。

### 环形图悬停

- 命中段：`stroke-width` +8、半径 +3，其余段透明度降到 0.28
- 圆心文字切换成该分类的**名称 + 金额 + 占比**，文字颜色跟随分类色
- 图例联动：悬停图例行也会高亮对应扇区，且该行把百分比换成具体金额

状态放在页面层（`ringHover`），两个组件共用，所以扇区与图例双向都能触发。

### 折线图悬停

- 鼠标横向位置换算成比例，吸附到最近的数据点（月视图 28–31 个点，年视图 12 个）
- 显示竖向虚线参考线、游标圆点、日期与金额浮层（如「10 月 12 日 · 周一 / ¥30.00」）
- 游标点用 HTML 覆盖层而不是 SVG `<circle>`：图表用了 `preserveAspectRatio="none"` 横向拉伸，
  SVG 里的圆会被拉成椭圆

### 验证方式

静态截图看不出悬停态，改用 CDP 模拟真实鼠标：

```bash
# 启动时开启调试端口
./鲸鱼记账.exe --remote-debugging-port=9222
```

Python 通过 `Input.dispatchMouseEvent` 把指针移到扇区中点、鲸鱼娘中心、折线图 72% 位置，
再 `Page.captureScreenshot` 取图。两个坑：WebSocket 握手带 Origin 会被拒（需要
`suppress_origin=True`）；`urllib` / `websocket-client` 会走系统代理导致连不上 127.0.0.1
（需要显式禁用代理）。
